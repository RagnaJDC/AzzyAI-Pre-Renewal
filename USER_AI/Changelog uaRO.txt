1.0
⦁	Ship defaults are PvE: PVPmode off, kite off
    H_Config and M_Config: PVPmode=0, KiteMonsters=0, ForceKite=0, UseBlockedKite=1.
    Turn on PvP or kite in AzzyAiConfigPreRe.exe when you want them.

⦁	Release 1.0: version locks, config v2.0, new AzzyAiConfigPreRe.exe
    CVersionuaRO is v1.0 and ConfigVersion is v2.0. Rebuild the GUI so Save
    writes UseBlockedKite and PVPAutoAllyOnGiveUp. File-size integrity matches
    the shipped Lua.

⦁	DoNotChase now applies to PvP players
    GetTact used to return the raw PvP chase field and skip the monster remap.
    CHASE_NORMAL is -1, so the pet walked at every PvP target even with
    DoNotChase=1. PvP chase now uses the same rule: ALWAYS chases, NEVER does
    not, NORMAL follows DoNotChase. CHASE_ALWAYS on a class row still closes.

⦁	Crash is an attack skill, not a debuff
    MER_CRASH was on DebuffSkillList / BasicDebuffs, so sword and lancer
    mercenaries treated it like Provoke instead of their main hit. It is now
    first on AtkSkillList. Extra files no longer put it back as a debuff.

⦁	Blocked-cell kite (UseBlockedKite)
    New kite picker: failed Moves mark that cell blocked (~650 ms), then the next
    dest is scored on an 8-direction ring that skips blocked/occupied cells, stays
    in Caprice/DS range and KiteBounds, and steps sideways if the ring is empty.
    While kiting it holds that range and casts on the walk — no walk-back onto the
    mob, no skill cancel of the kite dest. Owner's attacker is peeled if it is in
    skill sight; otherwise the pet's mob is hit and we kite toward the owner.
    Still needs KiteMonsters=1. Toggle is under Kiting Options in AzzyAiConfigPreRe.exe.

⦁	Ignore uaRO prt_in monster-model NPC at 174,136
    Same skip Azzy already used for the Eden Bathory at 174,33. The inn NPC uses
    a monster sprite, so IsMonster() made the pet chase it and get stuck. Standing
    actors on that cell are left out of the actor/target lists.

⦁	Caprice aftercast is 1500ms on uaRO unless a bard song is up
    Playtested floor: 1500 ms is accepted, anything lower spams cooldown delay.
    Reuse (field 9) stays 220–300 ms so Bragi/song-removed ACD can still recast
    fast. DoSkill skips field 6 while SingBuffed=1; without a song it waits 1500.

⦁	Fixed PvP friend/ally tactics being ignored in favour of class tactics
    GetPVPTact used to look up job class (Knight, Wizard, etc.) before the friend-list
    role. A teammate on FRIEND or ALLY still inherited the class attack row, so the
    homunculus/mercenary would chase guild and party members you had already friended.
    Lookup order is now actor ID, then friend-list role (FRIEND/ALLY/KOS/ENEMY), then
    job class, then default. Class rows apply only to players not on the friend list.
    Mercenaries now also read job class via GetV(V_HOMUNTYPE); they previously skipped
    class rows entirely. IsFriendOrSelf no longer treats KOS or ENEMY as teammates.

⦁	PvP auto-ally after give-up (PVPAutoAllyOnGiveUp, default on)
    When PVPmode=1 and the homunculus/mercenary gives up on a player it cannot acquire
    (chase give-up, attack lock fail, standpoint fail, attack timeout), that player is
    written to A_Friends.lua as ALLY. Class tactics then stop sending us back at late
    WOE/BG joiners the client will not lock. FRIEND, ALLY, RETAINER, PKFRIEND, KOS,
    and ENEMY are not overwritten. Toggle lives under PVP Options in AzzyAiConfigPreRe.exe.

⦁	Fixed idle walk system AggroHP dependency issue in PvP mode
    Resolved issue where idle walk would be disabled when HP dropped below AggroHP threshold, even in PvP mode where continuous movement is crucial.
    Added GetEffectiveAggroHP() helper function that overrides AggroHP to 0 for idle walk checks when PVPmode=1 is enabled.
    This ensures homunculus maintains defensive movement patterns regardless of HP level in PvP scenarios, while preserving normal AggroHP behavior for enemy targeting.

⦁	Improved PvP mode auto-configuration reliability
    Fixed PvP mode default settings override to always apply optimal configurations regardless of user settings.
    Removed redundant UseIdleWalk != 2 condition that could prevent proper PvP optimization when user had manually set UseIdleWalk=2 but other settings were incorrect.
    PvP mode now guarantees consistent application of UseIdleWalk=2, FollowStayBack=0, and IdleWalkSP=0 whenever PVPmode=1 is enabled.

These fixes should resolve DoNotChase issues within pvp, as chase status required tactics to work.
⦁    Updated H_PVP_Tact.lua & M_PVP_Tact.lua to accept all 13 tactics per entry, with defaults now set for all classes.
⦁    Updated AzzyAiConfigPreRe.exe to support the new PvP tactics files with 13 tactics, including correct save/load functionality and GUI improvements to allow editing all tactic settings.

0.95 Dev
⦁	Fixed rescue detection failure in GetEnemyList function for retainer cooperation
    Resolved issue where rescue system (aggro=-2) failed to detect valid targets due to perspective-dependent v[2] classification between homunculus and mercenary.
    Added rescue target detection bypass that maintains all existing rescue tactic validation via IsRescueTarget().
    Enables proper homunculus/mercenary rescue cooperation when one retainer is attacked by monsters.

⦁	Enhanced PvP Mode with Automatic Player Protection and Mobile Turret System
    PVPmode=1 now automatically enables player protection idle walk (UseIdleWalk=2) where homunculus moves in diamond pattern 
    around owner position to provide defensive coverage and enhanced battlefield positioning. No manual idle walk configuration required.
    
    Combined with DoNotChase=1, creates advanced mobile turret system for superior PvP positioning:
    - Automatically enables diamond movement pattern (imported from AIthort) for optimal protection coverage
    - Continuously moves around owner while maintaining attack capability on enemies within skill range
    - Ignores out-of-range enemies to prevent movement interruption and maintain positioning
    - Provides mobile turret behavior ideal for PvP scenarios with constant movement and opportunistic attacks
    - Works consistently in both high SP (IDLEWALK_ST) and low SP (IDLE_ST) states
    
    Replaces static crosswalk pattern with dynamic diamond movement for improved battlefield mobility and simplified PvP setup.
    Simply set PVPmode=1 for automatic player protection, or PVPmode=1 + DoNotChase=1 for full mobile turret functionality.

⦁	PVP Tactics overhaul! You can now add Homunculus and Mercenary tactics under PVP tactics PER class/job ID'S
    This means you can now add specific tactics in PVP/WOE/BG per class/job type so the Homun/Merc will react how you want to specific classes.
